# 项目复核与跟踪整合设计

日期：2026-07-29

## 目标

项目取得最终准入结果后，在复核详情页的风险结论后直接展示合同项目跟踪，减少审核人员在不同页面之间切换。审批阶段已经采集的信息应自动进入跟踪台账，避免重复填写；持续变化的回款、交付、签约和承诺情况继续按期维护并保留不可修改的历史快照。

## 范围

本次调整包括：

- 调整项目复核详情页的信息顺序。
- 增加外部审批结果中的独立“特批事项”字段。
- 建立审批资料到项目跟踪字段的确定性映射。
- 将自动映射字段改为只读展示。
- 根据采购参与情况和采购风险动态显示供应商跟踪分区。
- 调整 Excel 导入、导出和跟踪快照的数据合并规则。

不包括：

- 对接真实 OA 或外部审批系统。
- 修改回款、交付、签约和事业部反馈的现有业务字段。
- 新增供应商以外的动态跟踪分区。

## 页面结构

当项目状态为 `tracking` 或 `tracking_completed` 时，项目复核详情页按照以下顺序展示：

1. 项目概览与当前状态
2. 风险结论
3. 合同项目跟踪
4. 审批字段
5. 项目说明汇总
6. 访谈和流程记录
7. 流程处理与外部审批记录

项目仍处于等待外部审批、有条件准入待核查或已驳回状态时，不显示合同项目跟踪。页面导航仅显示当前实际存在的分区，避免链接到隐藏内容。

## 跟踪模块结构

采用单页顺序分区，不使用标签页。模块分为：

1. 审批基础资料
2. 项目整体情况
3. 签约跟踪
4. 回款执行跟踪
5. 交付执行跟踪
6. 供应商交付执行跟踪（条件显示）
7. 事业部跟踪反馈
8. 历史跟踪记录

### 审批基础资料

审批基础资料只读展示，不进入人工编辑表单：

| 跟踪字段 | 审批数据来源 |
|---|---|
| 销售 BU | `answers.salesBu` |
| 销售区域 | `answers.salesRegion` |
| 销售经理 | `answers.salesManager`，缺失时使用 `project.salesName` |
| 项目名称 | `answers.contractName` |
| 签约客户 | `answers.customerName` |
| 最终用户 | `answers.endUserName` |
| 签约合同金额 | `answers.contractAmountCny` |
| 线上审批 GM1 | `answers.gm1` |
| 商机/项目识别码 | 优先使用跟踪项目代码，否则使用 `answers.opportunitySerialNumber` |

页面上显示“来自审批资料”的来源标识。自动字段不允许在跟踪快照接口中覆盖。

### 项目整体情况

- `specialApprovalItems`：取外部审批结果中的独立特批事项。
- `financingSituation`：优先取 `answers.financingOverview`；没有说明时，根据 `hasFinancing`、直接和潜在垫资金额、垫资期限生成确定性摘要；明确不垫资时显示“未涉及垫资”。
- `projectSummary`：取项目说明汇总中的 `projectOverview`。
- `currentIssues`：仍为每期可编辑字段，用于记录跟踪期内的新问题。

前三项只读，`currentIssues` 进入每期跟踪快照。

## 特批事项

外部审批结果增加 `specialApprovalItems`：

- “已完成审批”和“有条件准入”时必填。
- “被驳回”时不要求填写。
- 有条件准入核查通过后沿用原值，不要求重复填写。
- 字段写入外部审批决定对象，并随审批事件保留当时内容。
- 自动展示在跟踪模块，导出到客户 Excel 的“特批事项”列。

外部审批的普通说明、驳回原因、条件准入原因和准入条件保持原有含义，不与特批事项混用。

## 供应商分区显示规则

供应商交付执行跟踪在满足任一条件时显示：

1. `answers.hasProcurement` 为 `true`。
2. 存在已触发且 `category` 为 `procurement` 的风险。

不满足条件时：

- 页面不渲染供应商跟踪输入项。
- 手工跟踪接口拒绝本期新增供应商字段。
- Excel 导入中的供应商字段不写入项目并返回明确校验错误。
- Excel 导出保持客户模板列结构，但对应供应商单元格留空。

回款、交付、签约和事业部反馈分区始终显示。

## 数据合并

系统将跟踪数据分成两类：

- 审批派生数据：每次读取和导出时从项目审批资料实时计算，不复制到历史快照。
- 跟踪期数据：只保存会随时间变化的字段，并采用现有不可变快照机制。

读取跟踪详情和 Excel 导出时，按以下优先级组合：

1. 审批派生字段使用当前审批资料。
2. 跟踪期字段使用最新快照。
3. 系统字段使用当前项目状态、更新时间和序号。

该规则防止历史快照覆盖审核人确认的审批事实，同时保证审批资料修正后页面和导出结果一致。

## API 与兼容性

- 外部审批结果接口增加 `specialApprovalItems`。
- 跟踪字段目录增加 `derived` 或等价的不可编辑标记，区别于系统字段和跟踪期字段。
- 跟踪快照接口拒绝修改派生字段。
- 旧项目没有 `specialApprovalItems` 时仍可读取；进入跟踪页面后显示“历史项目未登记特批事项”，不阻断既有跟踪流程。本次不增加已通过历史项目的审批结果更正入口。
- 现有历史快照中已保存的基础字段继续兼容读取，但页面和新导出忽略这些旧副本，使用审批派生值。

## 错误处理

- 通过或有条件准入但没有填写特批事项：返回业务校验错误，不改变项目状态。
- 非采购项目提交供应商跟踪字段：返回字段级错误，不保存本期快照。
- 自动映射来源缺失：页面显示“审批资料未填写”，不以空字符串伪装完整。
- Excel 导入遇到不适用的供应商字段：该行标记为错误，必须修正后才能确认导入。

## 测试

测试范围包括：

- 页面中项目跟踪紧接风险结论，且仅对最终通过项目显示。
- 审批基础资料和项目整体情况的字段一一映射。
- 派生字段只读且不能被快照接口覆盖。
- 特批事项在通过和有条件准入时必填，并进入审批历史、跟踪页面和 Excel。
- 采购参与或采购风险命中时显示供应商分区。
- 非采购项目隐藏供应商分区并拒绝供应商字段写入。
- 回款、交付、签约和事业部反馈始终可维护。
- 旧项目和旧快照保持兼容。
- Excel 导入和导出的列结构与客户模板一致。

## 验收标准

- 审核人员在风险结论后即可查看并维护跟踪信息。
- 审批阶段已存在的信息不需要重复填写。
- 特批事项有明确来源并可以审计。
- 不涉及采购的项目不会出现无关供应商表单。
- 每期变化继续形成不可修改的历史记录。
- 导出的 Excel 基本情况与审批资料一致，动态字段与最新跟踪记录一致。
