# 销售端“先介绍、后补问”整改设计

## 背景

客户要求销售先根据系统提示，完整介绍项目基本情况。系统随后将销售的整段介绍拆解并匹配到固定 Excel 审批模板；能够匹配的内容直接保存，只对未匹配、含糊或风险证据不足的信息继续追问。

现有流程虽然限制在五轮以内，但第一轮仍由系统直接列出多个离散问题，不符合客户希望的自然介绍方式。

## 目标

- 首轮引导销售围绕固定提纲自由介绍项目，而不是逐题作答。
- AI 从首轮整段介绍中尽量提取所有可信字段，并映射到 Excel 模板。
- 后续只询问仍缺失或无法确认的信息，不重复询问已经填写的字段。
- 总回答轮次仍不超过五轮，首轮介绍计入五轮。
- 保持现有技术栈、Agent 框架、风险规则和固定 Excel 导出方式不变。

## 交互设计

### 开始填写

欢迎页说明新流程：销售先进行一次完整项目介绍，系统自动整理到审批表，再补充少量缺项。

### 第一轮：项目介绍

系统显示一个介绍提纲，包含五个方面：

1. 项目与合同基本情况；
2. 客户、最终用户和销售归属；
3. 资金来源、付款及签约链条；
4. 采购、供应商、交付和垫资情况；
5. 项目价值、风险管控与承诺。

销售通过一个自由文本框或语音入口一次性介绍。提纲是表达辅助，不要求销售按固定编号回答，也不把每个 Excel 字段逐项展示给销售。

### 第二至第五轮：智能补问

AI 先从销售上一轮回答中提取所有置信度足够的字段并保存。系统基于持久化结果重新计算缺项和风险，只生成尚未回答的简洁问题：

- 已提取字段不再提问；
- 条件不适用的字段不提问；
- 同一主题的多个缺项合并成一个问题；
- 第五轮集中包含所有仍适用的缺项；
- 五轮结束后不产生第六轮。

### 确认与送审

字段和风险证据完整时，销售可以检查汇总并送后台复核。五轮结束仍有缺项时，系统明确列出缺失字段，不假装已完成。

## 技术设计

### 访谈编排

在 `interview-batches.ts` 中将第一轮定义为特殊的“项目介绍轮”。第一轮只返回一个带五方面提纲的开放问题。完成第一轮后，继续复用现有按字段缺失情况动态组批的能力；后续阶段重新排序为基础缺项、交易与风险、项目说明，最后一轮兜底。

批次识别不再只依赖旧的“第 1/5 轮，请按编号一起回答”文本，要兼容新首轮文案和已有未完成项目，避免恢复历史记录时轮次计算错误。

### Agent

保持现有 `ToolLoopAgent` 和工具不变。调整系统指令：

- 首轮回答视为项目整体陈述；
- 每轮从完整回答中扫描所有模板字段，不局限于当前提纲；
- 保存高置信度字段后再请求下一批问题；
- 不重复追问已有值，不推测未明确的信息。

### 销售端界面

- 欢迎页说明“先完整介绍、再智能补问”。
- 聊天页在首轮展示结构化介绍提纲卡片。
- 输入框首轮提示为“请完整介绍项目情况”，后续改为“补充本轮信息”。
- 处理中提示改为“正在整理并匹配审批表字段”。

提纲卡片由当前批次状态确定，只在项目尚未出现销售回答时显示；恢复项目时不会重复出现。

## 兼容与异常处理

- 已经开始旧五轮流程的历史项目继续按旧轮次计数，不强制重置。
- 模型未提取到任何字段时仍进入下一轮缺项追问，不丢失原始销售消息。
- 模型或网络失败时保留输入错误提示，允许销售重新发送。
- 条件字段只有在采购或垫资适用时才进入后续补问。

## 验收标准

1. 新项目第一条助手消息是项目介绍引导，并包含五方面提纲。
2. 第一轮只有一个开放式介绍任务，不出现六至十个逐项问题。
3. 销售首轮一次提供多个字段后，第二轮不再询问这些字段。
4. 后续问题只包含持久化后仍缺失的适用字段。
5. 第一轮计入总轮次，系统最多接受五次销售回答，不生成第六批问题。
6. 欢迎页、聊天页和移动端均能清楚表达新流程。
7. 现有固定 Excel 映射、风险引擎、后台复核和导出流程不回归。

## 测试

- 单元测试覆盖新首轮文案、提纲、轮次计数、已答字段跳过和第五轮兜底。
- Agent/路由测试覆盖最终回复仍使用服务端规范批次消息。
- 浏览器验证新建项目、首轮提纲展示、输入提示和移动端无横向溢出。
- 执行全量测试、ESLint 和生产构建。
