# 域外合同前置审批固定模板闭环设计

## 1. 目标

在不更换 Next.js 16、React 19、Vercel AI SDK 7 和 `ToolLoopAgent` 的前提下，将现有语音访谈原型完善为可在公司内网运行的首期业务闭环：销售访谈、确定性风险预审、原 Excel 模板回填、后台人工复核、已填写模板导出和项目留档。

首期以“域外合同前置审批表-2025年11月启用”为唯一受支持模板，通过版本化配置保留未来增加模板的能力。

## 2. 首期范围

### 2.1 包含

- 固定模板的字段、问题、填写指导和 Excel 单元格映射。
- 销售通过分享链接进入，创建或恢复一次项目填写。
- 文字输入和浏览器中文语音识别。
- Agent 从自然语言回答中提取多个结构化字段。
- 八类域外合同风险的确定性判断和条件追问。
- 项目整体说明、签约意义、风险管控措施和承诺条款的采集与整理。
- 待补充、待复核、已复核、待人工提交和已归档等状态流转。
- 管理端展示真实模板和项目数据，支持筛选、查看详情、修改答案、填写复核意见和确认复核。
- 在客户原始模板的固定位置回填并导出，保留工作表结构、合并单元格、审批标准和填写批注。
- 公司内网单机文件持久化，并通过 Repository 接口隔离存储实现。
- 审批适配器接口。没有审批接口时明确显示“待人工提交”，不得模拟提交成功。

### 2.2 不包含

- 真实 OA 或飞书 API 调用。
- 审批状态回调。
- 审批通过后的长期回款、利润、交付和承诺跟踪大屏。
- 任意 Excel 自动语义解析。
- 通用可视化模板设计器和规则设计器。
- 企业统一身份认证。首期仅适合受控内网试运行，正式上线前必须接入身份认证和角色权限。

## 3. 架构

系统保持 Next.js App Router 全栈结构，新增五个边界清晰的模块：

1. **模板域模型**：描述固定模板版本、字段、问题、填写说明、必填条件和目标单元格。
2. **规则引擎**：以纯 TypeScript 函数执行可审计的硬性风险规则。
3. **访谈编排**：`ToolLoopAgent` 负责理解、提取、追问和内容归纳；不得自行覆盖规则引擎结论。
4. **持久化仓储**：通过 Repository 接口保存模板和项目聚合，首期实现为内网文件存储。
5. **Excel 适配器**：基于原始工作簿回填固定单元格，并导出填写后的模板。

调用关系：

```text
React 页面
  -> Next.js API Routes
      -> ToolLoopAgent（语言理解和对话）
      -> Risk Engine（确定性判断）
      -> Repository（持久化）
      -> Excel Adapter（原表回填）
      -> Approval Adapter（首期待人工提交）
```

## 4. 领域模型

### 4.1 模板字段

```ts
type FieldType = 'text' | 'number' | 'percentage' | 'amount' | 'boolean' | 'rating' | 'date';

interface TemplateFieldDefinition {
  key: string;
  label: string;
  section: string;
  type: FieldType;
  required: boolean;
  requiredWhen?: ConditionDefinition;
  question: string;
  followUp?: string;
  guidance?: string;
  targetCells: string[];
}
```

`targetCells` 允许一个逻辑字段回填到多个单元格，或由导出适配器按模板版本进行组合写入。

### 4.2 项目聚合

```ts
type ProjectStatus =
  | 'interviewing'
  | 'preaudit_needs_input'
  | 'pending_review'
  | 'reviewed'
  | 'pending_manual_submission'
  | 'archived';

interface PreauditProject {
  id: string;
  templateVersion: string;
  token: string;
  salesName: string;
  status: ProjectStatus;
  answers: Record<string, FieldAnswer>;
  messages: InterviewMessage[];
  risks: RiskFinding[];
  narratives: ProjectNarratives;
  review?: ReviewDecision;
  createdAt: string;
  updatedAt: string;
}
```

每次状态变化更新 `updatedAt`，并在文件写入时采用临时文件加原子替换，避免进程中断产生半写文件。

### 4.3 风险结论

```ts
interface RiskFinding {
  ruleId: string;
  category: 'sales' | 'procurement';
  title: string;
  triggered: boolean;
  severity: 'blocking' | 'high' | 'medium';
  reason: string;
  impact: string;
  evidenceKeys: string[];
  missingKeys: string[];
  followUpQuestions: string[];
}
```

风险结论必须记录规则编号、原因、影响、证据字段和缺失字段，后台复核时可追溯。

## 5. 固定模板字段分区

模板配置至少覆盖：

- 特批项目情况：合同名称、合同总额、GM1、签约客户、最终用户、供应商、销售 BU、销售区域、销售经理。
- 风险反馈：签约客户、签约链条、付款形式、项目利润、纯外采项目、供应商资信、采购付款条款、避免二次分包。
- 项目整体说明：商机来源、项目背景及政策、签约链条及进展、资金来源及落实情况、商务条款、项目金额利润及收入确认、采购情况、供应商情况、采购条款、垫资情况。
- 项目签约意义：战略契合度、公司产品能力、项目延续性。
- 风险与管控：签约风险、交付风险、回款风险。
- 承诺：回款、交付、利润、供应商、新商机和其他承诺。
- 后台部门建议：保留 `B49` 标签，仅允许后台复核人员向合并填写区 `C49:H49` 的左上单元格 `C49` 写入内容。

模板 D21:D30 的批注内容进入对应字段的 `guidance`，作为 Agent 问题说明和后台填写提示。

## 6. 风险规则

规则引擎首期实现以下八组规则。

### 6.1 签约客户

- E 级或黑名单：阻断级风险。
- D 级：高风险，要求 100% 预付款；不足时命中。
- 回款健康度 5 级：阻断级风险。
- 客户评级或预付款比例缺失时不猜测结论，返回待补充问题。

### 6.2 签约链条

- 最终用户直签不命中。
- 一级分包可继续评估客户评级和预付款。
- 一级分包之后命中高风险。
- 链条层级、上游签署状态或资金方不明确时要求补充。

### 6.3 付款形式

- 非直签且存在背靠背付款时进入风险判断。
- 优质白名单客户允许进入升级审批，但仍记录风险。
- 非白名单客户按评级要求最低预付款比例：S 10%、A 20%、B 40%、C 60%、D 100%。
- 预付款比例低于对应要求时命中高风险。

### 6.4 项目利润

- GM1 小于或等于 5% 命中阻断级风险。
- 涉及销售渠道费用时，GM1 小于或等于 15% 命中高风险。
- GM1 以百分数数值存储，禁止依赖自由文本比较。

### 6.5 纯外采项目

- 外采成本占比大于或等于 85% 命中高风险。
- 即使比例低于 85%，若第三方承担核心交付责任，仍命中高风险。

### 6.6 供应商资信

- 供应商实缴资金小于采购额时命中高风险。
- 个体工商户命中阻断级风险。
- D 级或黑名单供应商命中阻断级风险。
- 未涉及采购时整组问题跳过。

### 6.7 采购付款条款

- 提前采购、直接垫资或潜在垫资均记录风险。
- 直接垫资金额小于 50 万且期限小于 3 个月时标记为“需一事一议”，否则为高风险。
- 潜在垫资金额不超过 200 万时标记为“需一事一议”，超过时为高风险。

### 6.8 避免二次分包

- 合同允许供应商未经许可二次分包时命中阻断级风险。
- 未明确限制二次分包时要求补充合同条款说明。

## 7. Agent 访谈设计

`ToolLoopAgent` 保留，并使用以下工具：

- `extractProjectFields`：从一次回答中提取一个或多个字段及置信度。
- `saveProjectFields`：只保存模板中存在且通过类型校验的字段。
- `evaluateProjectRisks`：调用规则引擎并返回最新结论。
- `getNextInterviewQuestion`：根据缺失必填字段、条件字段和风险缺口选择下一问题。
- `askRiskFollowUp`：针对命中风险的缺失证据追问。
- `draftProjectNarratives`：在结构化信息完整后生成整体说明、签约意义、管控措施和承诺建议。
- `markReadyForReview`：仅当必填字段完整且所有阻断性缺失项已回答时允许进入待复核。

下一问题的选择每次从 Repository 读取最新项目状态，不使用 Agent 创建时的静态 `answeredKeys` 快照，避免同一轮重复提问。

LLM 输出必须经过 Zod schema 校验。字段置信度不足时不得写入正式答案，只用于生成确认问题。

## 8. 数据流和状态流

### 8.1 销售端

1. 销售访问固定模板分享链接。
2. 输入姓名后创建项目；同名且仍处于访谈中的项目可恢复。
3. Agent 先收集基础项目字段，再根据是否涉及采购和当前风险动态追问。
4. 每次保存答案后重新执行规则引擎。
5. 必填项或风险证据不足时状态为 `preaudit_needs_input`。
6. 信息完整后生成说明草稿，销售确认后进入 `pending_review`。

### 8.2 管理端

1. 管理端读取真实项目列表，不使用 Mock 数据。
2. 复核人员查看答案、风险证据、对话记录和说明草稿。
3. 复核人员可修改答案；修改后重新执行规则引擎并记录复核时间。
4. 确认复核后状态改为 `reviewed`。
5. 导出成功后可标记为 `pending_manual_submission`。
6. 人工完成外部流程后可标记 `archived` 并填写外部单号或备注。

不允许从 `interviewing` 直接跳转到 `pending_manual_submission` 或 `archived`。

## 9. Excel 回填

系统保存原始模板二进制文件，不重新创建工作簿。导出步骤：

1. 加载原始模板。
2. 根据模板版本获取单元格映射。
3. 对顶部复合字段区域生成多行文本并写入对应合并区域的左上角单元格。
4. 将八类风险的“是否涉及及说明”写入 BU 填写列。
5. 将项目说明、签约意义、风险管控和承诺写入事业部反馈列。
6. 将后台复核建议写入后台部门建议区域。
7. 保留工作表名称、合并区域、列宽、行高、审批标准和原批注。
8. 使用项目名称和时间生成安全文件名并返回下载。

导出前校验原模板版本和关键锚点单元格。模板不匹配时返回可理解的错误，不生成可能错位的文件。

## 10. 持久化

首期使用文件仓储，目录默认位于项目运行目录下的 `data/`：

```text
data/
  templates/
    preaudit-2025-11.xlsx
  state/
    templates.json
    projects.json
```

约束：

- `data/state/*.json` 不提交真实业务数据到 Git。
- 写入先落临时文件，再原子替换正式文件。
- 启动时文件不存在则创建空集合；JSON 损坏时拒绝覆盖并返回明确错误。
- Repository 接口不暴露文件路径，使未来数据库实现可替换。
- 单机首期通过进程内写锁串行化修改，避免同时写入丢失更新。

## 11. API 边界

保留现有主要路径语义，并调整为项目域模型：

- `GET /api/admin/templates`：模板列表。
- `GET /api/admin/projects`：项目列表及筛选。
- `GET /api/admin/projects/[id]`：项目详情。
- `PATCH /api/admin/projects/[id]`：复核修改字段和意见。
- `POST /api/admin/projects/[id]/review`：确认复核。
- `POST /api/admin/projects/[id]/export`：导出原模板。
- `POST /api/admin/projects/[id]/archive`：登记人工提交信息并归档。
- `GET /api/s/[token]`：销售端模板概要。
- `POST /api/s/[token]/start`：创建或恢复项目。
- `POST /api/s/[token]/chat`：Agent 流式访谈。
- `POST /api/s/[token]/prepare-review`：生成并确认提交复核摘要。

旧的 submission 路径在迁移期间可保留只读兼容，管理端新代码只使用 projects 路径。

## 12. 错误处理

- LLM 不可用：保留已填写数据，提示用户稍后重试；规则引擎和人工编辑仍可使用。
- LLM 返回无效结构：拒绝写入并生成确认问题。
- 音频识别不可用：自动降级到文字输入。
- 文件写入失败：不改变内存中的成功状态，返回 500 和可定位的错误编号。
- Excel 模板锚点不匹配：拒绝导出并提示模板版本错误。
- 状态流转非法：返回 409，不隐式纠正。
- 外部审批接口未配置：返回“待人工提交”，不得返回模拟实例 ID。

## 13. 界面设计

### 13.1 销售端

- 欢迎页：显示固定模板名称、填写人姓名和隐私提示。
- 访谈页：保留聊天主界面；新增已收集字段进度、当前命中风险数量和缺失信息提示。
- 复核摘要页：按“基础信息、命中风险、项目说明、承诺”分区，允许返回继续补充。
- 完成页：明确显示“已提交后台复核”，不显示“已提交审批”。

### 13.2 管理端

- 模板页：展示固定模板版本和下载原模板，不提供误导性的任意模板上传。
- 项目页：真实列表、状态筛选和项目详情抽屉或详情页。
- 复核页：左侧结构化答案，右侧风险结论与证据，下方说明草稿和后台意见。
- 设置页：保留 LLM 和语音配置；审批配置标注“暂未接入”。

## 14. 测试策略

所有新增行为遵循测试先行。

### 14.1 单元测试

- 固定模板字段配置完整性和目标单元格唯一性。
- 八组风险规则的命中、不命中、边界值和缺失信息。
- 条件必填逻辑，例如未涉及采购时跳过供应商问题。
- 状态机合法与非法流转。
- 文件 Repository 的初始化、恢复、原子写入和损坏文件保护。
- 下一问题选择优先级。
- Excel 回填值和关键原始结构保持。

### 14.2 API 测试

- 创建和恢复项目。
- 更新答案后重新计算风险。
- 未完成项目不能复核。
- 未复核项目不能进入待人工提交。
- 导出返回正确文件类型和文件名。

### 14.3 浏览器验证

- 管理端不再出现 Mock 模板和 Mock 项目。
- 销售从欢迎页完成文字访谈、查看摘要并提交后台复核。
- 管理员完成复核并下载已填写模板。
- 无效 Token、LLM 不可用和非法状态显示清晰错误。

### 14.4 完成门槛

- 新增测试全部通过。
- `next build` 通过。
- ESLint 无错误。
- 实际客户模板回填后，关键单元格内容正确且合并区域、样式和批注仍存在。
- 本地服务重启后项目数据仍可读取。

## 15. 迁移策略

- 删除管理端 `MOCK_TEMPLATES` 和 `MOCK_DATA`。
- 将现有内存 Store 替换为 Repository；不迁移演示数据。
- 固定模板在首次启动时注册，分享 Token 使用稳定配置值，不因重启变化。
- 旧 README 的任意 Excel 上传说明替换为固定模板闭环说明。
- 飞书模拟提交函数停止被业务路径调用，保留审批适配器接口供后续实现。

## 16. 验收场景

使用客户模板完成以下场景即视为首期验收通过：

1. 销售填写 GM1 为 5%，系统命中项目利润阻断风险。
2. 销售填写涉及渠道费用且 GM1 为 15%，系统命中项目利润高风险。
3. 外采占比为 85%，系统命中纯外采风险。
4. 非直签、客户 B 级、背靠背付款、预付款 20%，系统指出至少需要 40% 预付款。
5. 未涉及采购时，系统不询问供应商和采购条款。
6. 涉及采购且供应商为个体工商户时，系统命中供应商资信阻断风险。
7. 复核人员修改预付款比例后，风险结果实时重算。
8. 导出文件使用原模板布局，包含销售答案、风险说明、项目说明和后台意见。
9. 服务重启后仍能读取项目、对话、风险和复核状态。
10. 未配置 OA/飞书接口时，系统显示待人工提交且不生成伪审批编号。
